    Migrate from 0.5 to 0.6¶

    0.6 is a breaking release for every package. The Rust core renames items for consistency and replaces strings and Booleans with typed values; every language package now uses those names, takes enums instead of integer codes, and drops the Config argument from validation. Upgrade the language package and its native library together: all packages are released as 0.6.0.

    Pick your language:

    Language Package Deprecated 0.5 names Migration page
    Rust fatoora-core = "0.6.0" Renamed items warn until 0.7; retyped items break Rust
    Python pip install "fatoority==0.6.0" Renamed names warn until 0.7; getters becoming properties breaks Python
    JavaScript / TypeScript npm install fatoority@0.6.0 new_ (use create) and the renamed adjustment members; getters becoming properties and other renames break JavaScript/TypeScript
    Kotlin / Java com.fatoority:fatoority:0.6.0 0.5 getter functions, String amount overloads and the renamed adjustment members warn until 0.7; other renames break Kotlin/Java
    C# / .NET Fatoority 0.6.0 New (use Create) and the renamed adjustment members; other changes break C#/.NET
    C / C++ Release archives None; every change breaks C/C++

    Where a language keeps deprecated names, they forward to the new ones and are removed in 0.7. A good order of work is to fix the compile errors (or, in Python and plain JavaScript, the property calls) first, then turn deprecation warnings into errors and replace what remains.

    In every language, builders use set* to replace a value and add* to append one, so flags, set_tax_exemption, set_note and set_payment_means_code become set_flags, add_tax_exemption, add_note and add_payment_means. The 0.5 aggregate allowance setters (invoice_level_discount, invoice_level_charge, allowance_reason, set_allowance) are replaced by allowance/charge entries with an explicit VAT category and rate.

    What changed per language¶

    • Rust: invoice inputs and getters use typed wrappers (InvoiceUuid, InvoiceTimestamp, CurrencyCode, InvoiceHash, VatId); the fields of invoice value types such as Address are private; Environment is #[non_exhaustive]; serialized adjustments use "kind" instead of "charge". See Rust.
    • Python: getters become properties; invoice data becomes frozen dataclasses (Address, Party, Adjustment, Identifier, ...); dates become datetime/date; keyword-only arguments are enforced. See Python.
    • JavaScript/TypeScript: value getters become read-only properties; optional text is string | null; amounts stay decimal strings; library failures throw FatooraError subclasses; validateZatca returns a plain object; new_ becomes create. See JavaScript/TypeScript.
    • Kotlin/Java: value getters become properties; amounts are BigDecimal; optional text is String?; failures throw BindingException subclasses. See Kotlin/Java.
    • C#/.NET: scalar getters become properties; amounts are decimal; optional text is string?; BindingErrorException becomes FfiException and its subclasses. See C#/.NET.
    • C/C++: functions are renamed with the core types, enums are typed and ZATCA validation returns a report object. See C/C++.

    The CLI's commands and flags are unchanged; a blank --previous-invoice-hash is now rejected as invalid options (exit code 3). The full list of changes, including additions, is in the changelog.
