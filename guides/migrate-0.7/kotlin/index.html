    Migrate from 0.6 to 0.7: Kotlin and Java¶

    This page covers the com.fatoority:fatoority and com.fatoority:fatoority-android packages. The overview lists the other languages.

    dependencies {
    implementation("com.fatoority:fatoority:0.7.0")
    // Android: com.fatoority:fatoority-android:0.7.0
}

    <dependency>
  <groupId>com.fatoority</groupId>
  <artifactId>fatoority</artifactId>
  <version>0.7.0</version>
</dependency>

    0.7 removes every @Deprecated member of the com.fatoora facade. Each replacement below already exists in 0.6, so the simplest path is to compile against 0.6 with warnings as errors (allWarningsAsErrors = true in Kotlin, -Xlint:deprecation -Werror in Java), apply each ReplaceWith hint, and then bump the version.

    Removed members¶

    Renamed aliases¶

    Removed Use instead
    Adjustment.percentage(base, percent) (factory) Adjustment.percentOf(base, percent)
    adjustment.withSuppliedAmount(value) adjustment.suppliedAmount(value)
    adjustment.percent property and adjustment.percent() adjustment.percentage (BigDecimal?); Java getPercentage()
    allowanceCharge.withoutVatRate() allowanceCharge.omitVatRate()
    vatBreakdown.withoutVatRate() vatBreakdown.omitVatRate()

    String amount overloads¶

    Every method that takes a quantity, price, rate or amount keeps only its java.math.BigDecimal overload. Wrap string literals in BigDecimal("...") (Java: new BigDecimal("...")); never go through Double.

    Removed String overload Use instead
    Adjustment.amount(value) Adjustment.amount(BigDecimal(value))
    Adjustment.percentOf(base, percent), Adjustment.percentage(base, percent) Adjustment.percentOf(BigDecimal(base), BigDecimal(percent))
    adjustment.suppliedAmount(value), adjustment.withSuppliedAmount(value) adjustment.suppliedAmount(BigDecimal(value))
    AllowanceCharge.create(kind, amount, reason, reasonCode, category, rate, exemption) The same call with amount and rate as BigDecimal
    allowanceCharge.withPercentage(base, percent) withPercentage(BigDecimal(base), BigDecimal(percent))
    InvoiceBuilder.addLineItem(description, quantity, unitCode, unitPrice, vatRate, category) The same call with quantity, unitPrice and vatRate as BigDecimal
    InvoiceBuilder.addAllowance(value, category, rate, exemption), addCharge(...), addTaxExemption(category, rate, exemption) The same calls with rate as BigDecimal
    InvoiceBuilder.setPrepaidAmount(amount), setPayableRoundingAmount(amount) The same calls with a BigDecimal
    InvoiceBuilder.setTaxCurrency(currency, amount) setTaxCurrency(currency, BigDecimal(amount))
    InvoiceLineItem.create(description, quantity, unitCode, unitPrice, rate, category) The same call with quantity, unitPrice and rate as BigDecimal
    LineItemBuilder.setInvoicedQuantity, setItemNetPrice, setItemGrossPrice, setItemPriceDiscount, setItemPriceBaseQuantity, setLineNetAmount, setLineVatAmount, setLineAmountWithVat, setVatRate (String argument) The same setters with a BigDecimal
    VatBreakdown.create(category, rate, taxableAmount, taxAmount, exemption) The same call with rate, taxableAmount and taxAmount as BigDecimal

    Boolean coroutine overloads¶

    Removed Use instead
    client.reportSimplifiedInvoiceAsync(invoice, credentials, clearanceStatus: Boolean, acceptLanguage) client.reportSimplifiedInvoiceAsync(invoice, credentials, ClearanceMode.Enabled or ClearanceMode.Disabled, acceptLanguage)
    client.clearStandardInvoiceAsync(invoice, credentials, clearanceStatus: Boolean, acceptLanguage) client.clearStandardInvoiceAsync(invoice, credentials, ClearanceMode.Enabled or ClearanceMode.Disabled, acceptLanguage)

    true maps to ClearanceMode.Enabled and false to ClearanceMode.Disabled, as in the blocking methods.

    Getter functions¶

    The 0.5-style getter functions are gone; read the property of the same name instead. In Kotlin drop the parentheses (address.city() becomes address.city); in Java call the generated getter (address.getCity()). is* and has* getters had no deprecated function and are unchanged.

    The property types differ from the removed functions in two ways:

    • Getters marked "was Text?" returned a closeable Text handle. The property is a nullable String, or a nullable BigDecimal for amounts (baseAmount, percentage, itemGrossPrice, itemPriceDiscount, itemPriceBaseQuantity, taxCurrencyAmount). Drop the .use { it.value() }.
    • Getters marked "was String" returned decimal text. The property is a BigDecimal; call toPlainString() where you need the text, and compare with compareTo, since returned values are normalized (10.50 reads back as 10.5).

    Text class¶

    com.fatoora.Text is removed, along with the internal com.fatoora.raw.Text. Only the removed getter functions returned it; every optional text property is already a String? in 0.6, so replace text.value or text.value() with the string itself and drop the use { } block.

    Code that calls the low-level com.fatoora.raw classes directly gets a String or String? wherever they returned Text. Their ValidationResponse.clearedInvoiceXml() and SignedInvoice.zatcaKeySignature() fail when the value is absent: check clearedInvoiceXmlPresent() or zatcaKeySignaturePresent() first. The com.fatoora properties are unchanged.

    Changed signatures¶

    These changes have no 0.6 equivalent to migrate to first; update the call when you upgrade.

    Client timeout¶

    ZatcaClient.withTimeout takes a duration instead of a Long millisecond count: a java.time.Duration from Java or Kotlin, or a kotlin.time.Duration from Kotlin. The timeout is rounded up to whole milliseconds; zero, negative, infinite and longer-than-4294967.295-second values throw IllegalArgumentException. Use ZatcaClient.create(config) for no client-side timeout.

    0.6 0.7
    ZatcaClient.withTimeout(config, 30_000) Kotlin: ZatcaClient.withTimeout(config, 30.seconds) (import kotlin.time.Duration.Companion.seconds)
    ZatcaClient.withTimeout(config, 30000L) (Java) ZatcaClient.withTimeout(config, Duration.ofSeconds(30)) (import java.time.Duration)

    Binary output¶

    Bytes.asSlice() is renamed Bytes.toByteArray(), the Kotlin name for a conversion that returns a new array. It still returns an independent copy that stays valid after the Bytes owner is closed.

    0.6 0.7
    bytes.asSlice() (Kotlin, ByteArray) bytes.toByteArray()
    bytes.asSlice() (Java, byte[]) bytes.toByteArray()

    Error classes¶

    0.7 gives every language the same error hierarchy: a base FatooraException, one ErrorKind enum, and one subclass per kind named <Kind>Exception. See errors and diagnostics. These names change in 0.7 with no deprecated alias in 0.6, so update them while upgrading.

    0.6 0.7
    BindingException FatooraException (same code, kind, message and detailsJson)
    ErrorKind, ErrorKind.fromCode(code) Unchanged
    No public factory FatooraException.fromCode(code, message, detailsJson)

    The subclasses (InvalidInputException, ..., ApiException) keep their names and constructors. A catch (error: BindingException) (Java catch (BindingException error)) becomes catch (error: FatooraException).

    Example¶

    // 0.6, with deprecation warnings
val city: String = address.city()
val district: String? = address.district()?.use { it.value() }
val payable: String = invoice.totals().use { it.payableAmount() }
Adjustment.percentage(BigDecimal("200"), BigDecimal("10")).use { /* ... */ }
builder.addLineItem("Notebook", "2", "PCE", "50", "15", VatCategory.Standard)
client.reportSimplifiedInvoiceAsync(signed, credentials, false)

    // 0.7
val city: String = address.city
val district: String? = address.district
val payable: BigDecimal = invoice.totals().use { it.payableAmount }
Adjustment.percentOf(BigDecimal("200"), BigDecimal("10")).use { /* ... */ }
builder.addLineItem("Notebook", BigDecimal("2"), "PCE", BigDecimal("50"), BigDecimal("15"), VatCategory.Standard)
client.reportSimplifiedInvoiceAsync(signed, credentials, ClearanceMode.Disabled)

    // 0.7 (Java)
String city = address.getCity();
String district = address.getDistrict();
BigDecimal payable;
try (InvoiceTotals totals = invoice.totals()) {
    payable = totals.getPayableAmount();
}
