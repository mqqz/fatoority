    ZATCA API client¶

    The API client requests credentials and submits signed invoices to the selected environment. For a runnable integration, start with the API guide. This reference describes inputs, returned data, and how to distinguish a completed request from an accepted invoice.

    Choose an operation¶

    Operation Required input Returns Behavior
    Issue compliance credentials CSR and OTP Compliance credentials (CCSID) Sends the CSR as Base64-encoded PEM.
    Issue production credentials Compliance credentials with a request ID Production credentials (PCSID) Uses the compliance request ID to request production credentials.
    Renew production credentials Existing production credentials, new CSR, OTP, response language Production credentials Submits a renewal request.
    Check invoice compliance Signed invoice and compliance credentials Validation response Checks the invoice; a passing check does not establish reporting or clearance.
    Report a simplified invoice Signed simplified invoice, production credentials, clearance flag, response language Validation response Rejects standard invoices before sending.
    Clear a standard invoice Signed standard invoice, production credentials, clearance flag, response language Validation response Rejects simplified invoices before sending.

    Credentials must match the client's environment. Production credentials describe the credential scope; they can belong to a test environment. The credential constructor stores supplied values; it does not authenticate them or obtain a certificate. Preserve the request ID returned during compliance onboarding.

    Input values¶

    Input Expected value Notes
    Configuration Selected environment Used for endpoints and credential environment checks.
    CSR Parsed or generated certificate signing request See CSR reference. Supply the matching private key separately when signing invoices.
    OTP Text supplied for the onboarding or renewal operation Sent in the OTP header. Invalid HTTP-header characters fail before transport.
    Token Binary security token returned by ZATCA Used with the secret for HTTP Basic authentication.
    Secret Credential secret returned by ZATCA Keep credentials out of logs.
    Request ID Optional text from credential issuance Required to request production credentials from compliance credentials.
    Invoice Signed invoice object The client sends its hash, UUID, and Base64 XML.
    Clearance flag ClearanceMode (Enabled/Disabled) in every language Sends Clearance-Status: 1 when enabled, 0 when disabled. It does not change the selected operation.
    Response language ar, en, or omitted Only the exact value ar selects Arabic; every other value sends English.

    Interpret an invoice response¶

    A successful HTTP status means that a response body was decoded. Check acceptance before treating an invoice as reported or cleared. The acceptance helper fails for both rejected and unknown outcomes.

    Invoked operation Accepted status Rejected status
    Reporting REPORTED NOT_REPORTED
    Clearance CLEARED NOT_CLEARED
    Compliance Validation status PASS or WARNING Validation status ERROR

    Missing or unrecognized endpoint status produces an unknown outcome. A positive status accompanied by validation errors also produces an unknown outcome. Warnings alone do not prevent acceptance. Only the status for the operation actually invoked determines its outcome.

    Returned field Value Meaning
    HTTP status Optional integer Actual response status, when attached by the client.
    Outcome Accepted, rejected, or unknown Classification for the invoked operation.
    Validation results Result object Contains message collections and optional overall status.
    Reporting / clearance status Optional status enum (Python: optional text) Gateway status for each operation; unrecognized values map to Other/Unknown, and the bindings' *_raw getters return the exact text.
    Seller / buyer QR status Optional text Raw QR status returned by the gateway.
    Cleared invoice Base64 Optional text Exact encoded invoice returned by clearance.
    Cleared invoice XML Optional decoded text Preserves returned text; does not parse XML or verify its signature.

    Missing cleared XML is independent of acceptance. A present empty Base64 value, invalid Base64, NUL bytes, or invalid UTF-8 fails decoding.

    Validation results contain information, warning, and error message collections, which can be empty, plus an optional status. Each message has optional type, code, category, message text, and status fields. Handle missing fields instead of assuming that every response contains a complete diagnostic.

    HTTP failures and custom transport¶

    Invoice operations treat every non-2xx response as an error, including 400 and 409. A duplicate-reporting 409 does not establish that an earlier submission was rejected. A 208 clearance response follows the successful-response path and still requires an acceptance check. Redirects are not followed; a 303 does not trigger automatic reporting. A malformed successful body is a decoding error, and a failed body read is a transport error.

    No client-side request timeout applies by default. Construct the client with a timeout to bound each request, from connecting until the response body is read. A request that exceeds it fails as a network (transport) error. A zero timeout is rejected as invalid input (ErrorKind::InvalidInput, details type invalid_timeout). JavaScript has no timeout option: its client sends through the fetch you supply, so bound requests there with an AbortSignal.

    Credential issuance requires a successful response. Renewal additionally supports the gateway's 428 renewal response when it contains a decodable credential body.

    Where exposed, prepared requests let you use your own HTTP transport. Preparing performs input checks and builds an owned request without sending it. Send its method, URL, headers, and body, then pass the actual HTTP status and response bytes to its decoder. Headers contain credentials. The decoder preserves the operation context needed for acceptance checks. Keep redirects disabled in custom transports.

    Language reference¶

    Import client, credential, and response types from fatoora_core::api. ZatcaClient::new(config: Config) returns Result<ZatcaClient, ZatcaError>. ZatcaClient::with_timeout(config: Config, timeout: Duration) does the same with a per-request timeout; a timeout surfaces as ZatcaError::Http (or ZatcaError::ResponseRead mid-body), both ErrorKind::Network. A zero timeout returns ZatcaError::InvalidTimeout (ErrorKind::InvalidInput). HTTP methods are async; call them with .await. Inputs below are borrowed.

    HTTP operations

    Method on client Returns after .await
    request_compliance_csid(csr: &Csr, otp: &str) Result<ComplianceCsid, ZatcaError>
    request_production_csid(ccsid: &ComplianceCsid) Result<ProductionCsid, ZatcaError>
    renew_csid(pcsid: &CsidCredentials<Production>, csr: &Csr, otp: &str, accept_language: Option<&str>) Result<CsidCredentials<Production>, ZatcaError>
    check_invoice_compliance(invoice: &SignedInvoice, credentials: &CsidCredentials<Compliance>) Result<ValidationResponse, ZatcaError>
    report_simplified_invoice(invoice: &SignedInvoice, credentials: &CsidCredentials<Production>, clearance_mode: ClearanceMode, accept_language: Option<&str>) Result<ValidationResponse, ZatcaError>
    clear_standard_invoice(invoice: &SignedInvoice, credentials: &CsidCredentials<Production>, clearance_mode: ClearanceMode, accept_language: Option<&str>) Result<ValidationResponse, ZatcaError>

    ClearanceMode::Enabled / ClearanceMode::Disabled send the Clearance-Status header as 1 / 0; ClearanceMode::from(flag) converts a bool. The prepare_report_simplified_invoice / prepare_clear_standard_invoice variants take the same arguments.

    Credentials

    CsidCredentials::<Compliance>::new(env, request_id, token, secret) creates compliance credentials; use Production for production scope. ComplianceCsid and ProductionCsid are aliases for CsidCredentials<Compliance> and CsidCredentials<Production>. Arguments are Environment, Option<String>, and two impl Into<String> values. Construction returns the credential object directly.

    credentials.request_id() Option<&str>
    credentials.binary_security_token() / credentials.secret() &str

    Method Returns
    response.http_status() Option<u16>
    response.outcome() InvoiceOutcome::{Accepted, Rejected, Unknown}
    response.ensure_accepted() Result<(), ZatcaError>
    response.validation_results() &ValidationResults

    response.clearance_status() Option<&ClearanceStatus>: Cleared, NotCleared, Other(String)

    The status enums are non-exhaustive. A value they do not recognize is kept verbatim in Other; as_str() and Display return the exact wire text. These getters borrow the response. Serializing and deserializing the response body does not preserve HTTP status or operation context; the deserialized outcome is Unknown. ZatcaError::NotAccepted retains the response. For HTTP failures, ZatcaError::http_status() provides the status when available; HttpResponseError::body() and validation_response() expose the retained body and optional parsed response. See error reference.

    Prepared requests

    Prefix each HTTP method above with prepare_ and use the same arguments. These synchronous methods return Result<ComplianceRequest, ZatcaError> for CSR issuance, Result<ProductionRequest, ZatcaError> for production issuance/renewal, and Result<InvoiceRequest, ZatcaError> for invoice operations.

    prepared.request() borrows an HttpRequest. Its method() and url() return &str, headers() returns &[(String, String)], and body() returns &[u8]. prepared.decode(status: u16, body: &[u8]) returns the corresponding response or credentials in Result<_, ZatcaError>. Preparing and decoding do not consume inputs. The request owns its data and can outlive the client, invoice, and credentials.

    Import ZatcaClient, ComplianceCsid, ProductionCsid, ClearanceMode, and InvoiceOutcome from fatoora. Construct ZatcaClient(config: Config, *, timeout=None); timeout is seconds (int/float) or a datetime.timedelta, and a request that exceeds it raises NetworkError. HTTP calls block until they finish and raise classified exceptions on failure; see errors.

    Asynchronous client

    AsyncZatcaClient(config: Config, *, timeout=None, http_client: Optional[httpx.AsyncClient] = None) has the HTTP operations above as async def methods with the same arguments, return types, and errors. It needs the async extra (pip install "fatoority[async]"), which adds httpx; the native library prepares and decodes each request and httpx sends it, without following redirects. Use async with or await client.aclose(); the client closes the httpx.AsyncClient it created, never one passed as http_client. A transport failure or timeout raises NetworkError. See the Python reference.

    Import ZatcaClient, ComplianceCsid, ProductionCsid, and InvoiceOutcome from fatoority. Create new ZatcaClient(config, { fetch }); the second argument is optional and defaults to globalThis.fetch. Calls return promises; use await.

    Method on client Promise resolves to
    requestComplianceCsid(csr, otp, options = {}) ComplianceCsid
    requestProductionCsid(credentials, options = {}) ProductionCsid
    renewCsid(credentials, csr, otp, acceptLanguage = null, options = {}) ProductionCsid

    Pass Csr for csr, SignedInvoice for invoice, strings for OTP/language, and ClearanceMode.Disabled or ClearanceMode.Enabled for clearanceMode, which is required; any other value, including a boolean or the variant name, rejects with a TypeError. Transport failures reject with NetworkError (host error in cause); response/acceptance failures reject with the FatooraError subclass for their code, such as ApiError or UnauthorizedError. See JavaScript HTTP setup for browser CORS and custom fetch behavior.

    Prepared requests

    For custom transport, import ZatcaClient as RequestClient from fatoority/raw and create it with RequestClient.create(config). Its synchronous methods are prepareRequestComplianceCsid, prepareRequestProductionCsid, prepareRenewCsid, prepareCheckInvoiceCompliance, prepareReportSimplifiedInvoice, and prepareClearStandardInvoice. They take the same operation arguments as above, without options; supply a ClearanceMode (not a boolean) and nullable language explicitly. They return ComplianceRequest, ProductionRequest, or InvoiceRequest according to the operation.

    request.method, url, and headersJson are strings; body() returns Bytes; toUint8Array() copies it. request.decode(status, body) takes an HTTP status number and a Uint8Array and returns the corresponding credentials or validation response. Alternatively, await sendPrepared(request, { fetch, signal }) from fatoority sends and decodes the request. Preparation owns its data; it does not send HTTP.

    Use the Fatoora namespace. ZatcaClient.Create(config: Config) returns a client; ZatcaClient.WithTimeout(config, timeout: TimeSpan) adds a per-request timeout, rounded up to whole milliseconds, that raises NetworkException when exceeded; a zero, negative, or over-uint.MaxValue-millisecond timeout throws ArgumentOutOfRangeException. HTTP methods block; errors throw FatooraException subclasses such as NetworkException or UnauthorizedException. Use using for owned objects, including child responses. Scalar getters are read-only properties.

    Responses

    Each getter takes const FatooraValidationResponse *self, the output argument below, then FatooraError **error. ensure_accepted takes only self and error.

    Function Output
    fatoora_validation_response_http_status uint16_t *out, bool *has_value
    fatoora_validation_response_outcome FatooraInvoiceOutcome *out
    fatoora_validation_response_ensure_accepted No output; FATOORA_OK only if accepted.
    fatoora_validation_response_validation_results FatooraValidationResults **out
    fatoora_validation_response_reporting_status FatooraReportingStatus *out, bool *has_value

    fatoora_validation_response_clearance_status FatooraClearanceStatus *out, bool *has_value

    Optional text returns NULL for absence, distinct from a present empty string. Status enum getters set *has_value to false when the field is absent; a present value this binding version does not recognize is written as the *_UNKNOWN enumerator (such as FATOORA_REPORTING_STATUS_UNKNOWN), and the _raw getter returns the exact wire string. Result getters use the fatoora_validation_results_ prefix: status(self, FatooraValidationStatus *out, bool *has_value, error) returns the optional status and status_raw(self, char **out, error) its text; info_len, warning_len, and error_len use size_t *out; info_message, warning_message, and error_message take self, zero-based size_t index, FatooraValidationMessage **out, and error. Indexes must be below the corresponding length.

    Message getters use fatoora_validation_message_ with suffixes message_type_raw, code, category, message, and status_raw. Each takes self, char **out, and error, returning optional owned text. message_type writes FatooraMessageType *out and status writes FatooraValidationStatus *out, each with bool *has_value.

    Prepared requests

    Add prepare_ after fatoora_zatca_client_ in the six HTTP function names above. Inputs are identical; the output changes to FatooraComplianceRequest ** for CSR issuance, FatooraProductionRequest ** for production issuance/renewal, or FatooraInvoiceRequest ** for invoice operations.

    Request accessors use fatoora_compliance_request_, fatoora_production_request_, or fatoora_invoice_request_. method, url, and headers_json take self, char **out, and error; body uses FatooraBytes **out. decode takes self, uint16_t status, const uint8_t *body, size_t body_len, the matching credential/response output pointer, and error. The request owns its data and does not send HTTP until your transport does so.

    Ownership

    Outputs and response children are independent owned copies. Release text with fatoora_string_free; release handles with their matching _free function, such as fatoora_zatca_client_free, fatoora_compliance_csid_free, fatoora_production_csid_free, fatoora_validation_response_free, fatoora_validation_results_free, fatoora_validation_message_free, or fatoora_invoice_request_free. See C ownership and errors.
